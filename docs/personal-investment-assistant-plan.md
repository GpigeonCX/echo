# 个人投资全景助手 0 到 1 需求梳理

## 1. 项目目标

把当前基于 Excel 的投资组合跟踪与进场计划，演进成一个简单、易上手、可多端使用的软件。

第一阶段先支持 Web 使用，满足日常投资管理。
后续阶段支持 iOS App。

核心原则：

- 尽量少手工录入
- 只记录关键操作，如买点、卖点、转账、现金变动
- 行情、净值、收益、回撤、历史峰值、计划偏离等自动计算
- 保持交互简单，不做专业交易终端那种复杂界面

## 2. 你当前 Excel 已有能力

从现有模板看，已经有比较清晰的投资方法论基础：

- 组合跟踪
- 目标权重管理
- 再平衡提示
- 历史峰值与回撤观察
- 弹药仓管理
- 分批进场计划
- 区分基金、现金、港股等资产

这说明软件不需要从“投资逻辑”重新设计，而是要把现有逻辑产品化、自动化。

## 3. 当前痛点

- 净值、价格需要手动更新
- 收益和收益率需要依赖手工填数
- 历史峰值可能漏记，导致回撤不准
- 回撤触发后的弹药投入需要手工判断
- 计划执行和实际持仓容易偏离
- Excel 在手机端、跨端使用体验较差
- 港股、基金、现金混合管理时，录入和查看不统一

## 4. 产品愿景

做一个“个人投资驾驶舱”。

用户只需要做 3 件事：

1. 配置投资目标和规则
2. 记录真实发生的买入、卖出、转入、转出
3. 查看系统自动生成的状态、提醒和建议

系统自动完成：

- 拉取行情/净值
- 更新持仓市值
- 计算收益、持仓占比、偏离度
- 自动维护历史峰值
- 自动计算当前回撤
- 自动判断是否触发分批加仓或再平衡
- 自动展示计划执行进度

## 5. 用户范围

首期核心用户就是你这类个人投资者，特征如下：

- 主要投资公募基金
- 有部分现金仓位
- 有部分港股股票
- 关注长期配置与分批进场
- 关注回撤控制和再平衡
- 希望低频操作，但高质量跟踪

这意味着产品首期应优先支持“资产配置型投资者”，而不是短线交易者。

## 6. 核心业务对象

系统至少要有以下数据对象：

### 6.1 资产标的

- 代码
- 名称
- 类型：基金 / 港股 / 现金 / 货币基金 / 其他
- 市场：A 股基金 / 港股 / 现金管理
- 币种：CNY / HKD / USD
- 是否允许自动拉行情

### 6.2 账户

- 账户名称
- 账户类型：券商 / 基金平台 / 银行 / 虚拟账户
- 账户币种

### 6.3 交易记录

- 交易时间
- 标的
- 动作：买入 / 卖出 / 转入 / 转出 / 分红 / 手工修正
- 成交数量
- 成交价格
- 手续费
- 账户
- 备注

### 6.4 投资计划

- 计划名称
- 计划总金额
- 起始时间
- 分批月数
- 首月投入比例
- 适用资产范围
- 计划状态：未开始 / 进行中 / 已完成 / 已暂停

### 6.5 目标配置规则

- 标的
- 目标权重
- 约束版本，如“长期目标”“美股不可买”
- 再平衡阈值

### 6.6 风险规则

- 历史峰值口径
- 回撤分档
- 每档动作，如投入 1/3 弹药
- 是否启用提醒

## 7. MVP 功能范围

MVP 只做最有价值、最常用的能力，不追求一次做全。

### 7.1 资产与持仓管理

- 维护资产标的列表
- 维护当前持仓数量和成本
- 支持基金、港股、现金三类资产
- 支持多币种，但首期展示统一折算成人民币总览

### 7.2 行情与净值自动更新

- 自动获取基金净值
- 自动获取港股价格
- 自动更新组合总市值
- 自动记录每日组合净值快照

### 7.3 交易驱动更新

- 用户只录入买入、卖出、转账、现金变化
- 系统自动更新持仓、成本、市值、收益

### 7.4 组合看板

- 组合总资产
- 今日收益、累计收益
- 持仓分布
- 目标权重 vs 当前权重
- 偏离度
- 历史峰值
- 当前回撤
- 最大回撤

### 7.5 进场计划管理

- 创建一次进场计划
- 配置总金额、周期、首月比例
- 自动拆分到各标的
- 展示计划执行进度
- 提示本月建议买入金额

### 7.6 回撤与弹药规则

- 自动维护组合历史峰值
- 自动计算当前回撤比例
- 当达到 -15%、-25%、-35% 等阈值时给出提醒
- 显示建议动用多少弹药

### 7.7 再平衡提醒

- 根据目标权重和阈值判断偏离
- 提示建议买入或卖出金额
- 先给建议，不自动下单

## 8. 暂不纳入 MVP

这些需求有价值，但不建议首期就做：

- 券商/基金平台自动同步持仓
- 自动下单
- 复杂税务处理
- 高级绩效归因
- 社区/分享功能
- 期权、债券、加密货币等多资产扩展
- 多用户协作

## 9. 关键页面设计

为了保持简单，首期 Web 建议只做 5 个页面。

### 9.1 首页总览

- 总资产
- 今日盈亏
- 累计收益
- 当前回撤
- 历史峰值
- 持仓分布图
- 待执行提醒

### 9.2 持仓页

- 各标的持仓
- 成本价
- 当前价/净值
- 市值
- 收益额
- 收益率
- 当前权重
- 偏离提示

### 9.3 计划页

- 当前进场计划
- 本月建议投入
- 已投入 vs 应投入
- 各标的拆分建议

### 9.4 交易记录页

- 新增买入卖出
- 新增现金变动
- 交易流水列表

### 9.5 设置页

- 目标权重
- 再平衡阈值
- 回撤分档
- 行情更新频率

## 10. 自动化计算规则

这部分是产品成败关键，建议尽早固化。

### 10.1 历史峰值

- 以“组合总资产”日级快照为准
- 每次行情更新后自动比对并刷新峰值
- 不依赖手工输入

### 10.2 回撤

- 当前回撤 = (当前总资产 - 历史峰值) / 历史峰值

### 10.3 当前权重

- 当前权重 = 标的当前市值 / 组合总市值

### 10.4 偏离度

- 偏离度 = 当前权重 - 当前采用目标权重

### 10.5 再平衡建议金额

- 建议交易额 = 目标市值 - 当前市值

### 10.6 计划执行进度

- 应投入金额按计划自动生成
- 已投入金额来自实际交易记录汇总
- 差额即本期待执行金额

## 11. 数据来源建议

这是实现自动更新的关键依赖，建议首期先按“够用”原则做。

### 11.1 基金

- 拉取公募基金净值
- 需要考虑净值通常按日更新，不是实时

### 11.2 港股

- 拉取港股延时行情即可
- 首期不追求盘口级实时数据

### 11.3 汇率

- 港股资产需要 HKD/CNY 汇率换算

### 11.4 快照策略

- 行情更新后生成组合快照
- 至少保留日快照，便于峰值和回撤计算

## 12. 推荐技术路线

为了兼顾 Web 先行和未来 iOS，建议技术上尽量复用。

### 12.1 前端

- Web：React + Next.js
- UI：优先简单、表格友好、移动端可适配
- 后续 iOS：
  - 方案 A：先做响应式 Web/PWA，后续再封装 App
  - 方案 B：未来使用 React Native 复用部分业务逻辑

### 12.2 后端

- Node.js + NestJS 或 Next.js API Routes
- 如果想要更快落地，首期可直接用 Next.js 全栈

### 12.3 数据库

- PostgreSQL

### 12.4 定时任务

- 定时拉取基金净值、港股价格、汇率
- 定时生成资产快照

### 12.5 部署

- Web 首期可部署在 Vercel 或自有服务器
- 如果用定时任务和数据库，通常自有云主机或支持 cron 的平台更稳

- 明确支持哪些资产类型

- 明确回撤和峰值的口径

- 画出 5 个核心页面低保真原型

### 里程碑 2：数据模型搭建

- 设计资产、账户、交易、计划、快照、规则表
- 初始化数据库
- 准备样例数据

### 里程碑 3：MVP 后端

- 资产管理接口

### 里程碑 5：规则引擎

- 回撤计算

## 15. 首期最小可用版本建议

如果目标是尽快用起来，建议把第一版压缩到以下范围：

- 仅支持一个用户
- 仅支持基金、港股、现金
- 仅支持手工录入交易
- 自动拉行情
- 自动算收益、峰值、回撤
- 自动给出再平衡和计划提醒
- 不接券商账户
- 不做自动下单

这样可以最快验证产品价值。

## 16. 你这个产品最关键的 3 个能力

不是页面多，而是下面这 3 个能力必须做准：

1. 行情更新后，持仓和收益自动刷新
2. 历史峰值与回撤自动维护，不能漏
3. 实际交易和计划目标自动对比，随时知道是否偏离

如果这三点做好，软件就已经明显优于 Excel。

## 17. 下一步建议

建议按下面顺序推进：

1. 先把 Excel 模板抽象成正式的数据模型和字段定义
2. 再画 Web MVP 原型
3. 然后确定技术栈和目录结构
4. 最后开始开发第一版

## 18. 我建议你优先确认的几个问题

- 组合统计是否按“全部资产总览”做主视角？
- 港股是按实时股数持仓管理，还是只看金额层面？
- 基金交易是否需要记录申购确认延迟和净值确认日期？
- 现金仓是否只看人民币，还是需要多币种现金账户？
- 提醒方式是否只需要站内提示，还是需要微信/邮件/推送？
